Build a production-ready WhatsApp bot using Node.js and Baileys v7.0.0-rc.14.

The bot should be modular, secure, easy to maintain, and suitable for deployment on a VPS, cPanel Node.js hosting, or similar Node.js hosting.

1. Core Requirements

Use:

- Node.js 20+
- "@whiskeysockets/baileys@7.0.0-rc.14"
- ES Modules or CommonJS consistently throughout the project
- "pino" for logging
- "dotenv" for environment configuration
- "qrcode-terminal" for local QR login
- "libphonenumber-js" or another reliable method for JID/phone normalization where needed

Do NOT use deprecated Baileys APIs.

Use the current Baileys v7 APIs and event structure.

The project must have:

- Automatic authentication/session handling
- Automatic reconnection
- Connection state monitoring
- Graceful shutdown
- Error handling
- Anti-crash protection
- Command cooldown/rate limiting
- Permission checking
- Group metadata caching where appropriate
- Clean logging
- Environment variables for secrets/configuration

4. Secure Connection System

Create a dedicated connection module.

The connection system must:

- Use Baileys v7.0.0-rc.14 correctly
- Load credentials using the appropriate auth-state system
- Automatically reconnect after temporary connection failures
- Detect logged-out sessions
- Avoid infinite reconnect loops
- Handle "connection.update"
- Handle "creds.update"
- Persist credentials safely
- Print QR code when authentication is required
- Support pairing-code login if appropriate
- Gracefully close the socket
- Handle SIGINT/SIGTERM
- Prevent multiple WhatsApp socket instances from being created accidentally

Implement exponential backoff for reconnect attempts.

Do not blindly reconnect when the session has been permanently logged out.

Create a central "handler.js".

It must:

1. Receive incoming messages.
2. Ignore invalid messages.
3. Ignore bot messages where appropriate.
4. Extract:
   - sender

   - message type
   - text
   - command
   - arguments
   - quoted message
5. Detect whether the chat is a group.
6. Retrieve group metadata when required.
7. Determine:
   - bot admin status
   - sender admin status
   - sender owner status
8. Apply command permissions.
9. Apply cooldown/rate limits.
10. Dynamically load commands.
11. Execute the correct command.
12. Catch command errors without crashing the bot.

Support commands such as:

9. Anti-Link System

Implement:

.antilink on
.antilink off
.antilink warn
.antilink kick

Allow configuration per group.

Detect common links such as:

- WhatsApp group links
- Telegram links
- Discord links
- Facebook links
- Instagram links
- TikTok links
- YouTube links
- Generic URLs

Do not block trusted domains if a whitelist is configured.

When a prohibited link is detected:

1. Delete the message if the bot has permission.
2. Warn the sender.
3. Track warnings.
4. Optionally kick the user after a configurable number of warnings.

Never allow the bot to kick administrators unless explicitly configured.

Protect against false positives.
